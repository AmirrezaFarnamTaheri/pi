# Enabling manual CI for fork performance PRs

GitHub's default-branch `.github/workflows/ci.yml` must contain
`workflow_dispatch` before **Actions → CI → Run workflow** can be used.

This small bootstrap change adds manual dispatch and push triggers for
`hardening/**`, `perf/**`, `sync/**`, and `ci/**`. Existing main, release
tag and pull-request tests remain unchanged. It does not grant new permissions,
change build or test commands, publish artifacts or introduce credentials.

## After reviewing/merging this bootstrap PR

1. Open **Actions → CI** on this fork.
2. Choose **Run workflow**, select a branch with pending work, then run it.
3. Verify the resulting run's head commit SHA and all six CI jobs.
4. Repeat for PR #4 (hardening), #7 (observability), #8 (token budgets),
   #9 (scheduling), #10 (event stream), #11 (TUI Markdown), and #12
   (model registration).
5. If GitHub denies dispatch, check **Settings → Actions → General** and
   whether the workflow is enabled; a token generated by an app may not
   automatically trigger another workflow.

Manual dispatch is an explicit owner action. Merely opening this PR does
not activate workflow_dispatch on the fork's default branch.

The broader hardening PR #4 also includes workflow independence changes and
is deliberately not merged until verified.
